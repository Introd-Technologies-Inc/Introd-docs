## Lifecycle labels

An introduction record moves through these labels:

| Label | Use it for |
| --- | --- |
| Requested | A request has been created for connector review |
| Connector approved | The connector accepted the review |
| Recipient accepted | The target accepted their own private review |
| Intro sent | The introduction has been recorded as made |
| Response recorded | A reply has been recorded |
| Follow-up planned | A follow-up has been planned |

## List tabs

On [Introductions](https://app.getintrod.ai/introductions), the tabs group records as **All introductions**, **Requested**, **Drafting**, **Connector reviewing**, **Awaiting response**, **Connected**, and **Closed**. The **Introductions** item in the sidebar can show a badge with the number awaiting a response.

Labels reflect stored status. They do not independently confirm that a message was delivered, that a person replied, or that a meeting happened.

## Keep status grounded in evidence

Record an event only after you have confirmed it in the channel where it happened. Introd's own guidance is to "record the introduction only after the connector sends it."

<Warning>
  Several displayed labels can map to broader stored states. Use the selected record's details and your own communication history as the source of truth. Changing a status or cancelling a record updates Introd only; it does not send, retract, or cancel a message elsewhere.
</Warning>
